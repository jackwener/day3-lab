## 一、测试分层

| 层级 | 工具 | 覆盖对象 | 说明 |
|------|------|----------|------|
| **L1 Unit** | pytest | 单个函数/类的逻辑（Storage、Agent、ReportParser、MarketData） | 不依赖网络，最快 |
| **L2 Integration** | pytest + Flask test_client | API 端点 + 存储 + 智能体调用 | 模拟 HTTP 请求 |
| **L3 Contract** | pytest + schema 断言 | 响应体结构与 `09` 一致 | 验字段名、类型、枚举值 |
| **L4 E2E** | 手动/浏览器测试 | 完整用户旅程 | 浏览器级操作 |

## 二、用例拆分原则

> **核心理念：数"可独立失败的点"** — 每条 TC 只回答一个问题，失败时一眼定位。

## 三、US-001 会话管理（TC-001 ～ TC-005）

| TC | 端点 | 场景 | 断言 |
|----|------|------|------|
| TC-001 | POST /sessions | 创建会话，title 默认"新会话" | 201, session_id 为 32 字符 hex, status=active, query_count=0 |
| TC-002 | POST /sessions | 创建会话，自定义 title | 201, title 匹配输入值 |
| TC-003 | GET /sessions | 获取活跃会话列表 | 200, 仅含 status=active, 按 created_at 倒序 |
| TC-004 | DELETE /sessions/<id> | 软删除会话 | 200, status=deleted, 有 deleted_at |
| TC-005 | GET /sessions/<id>/records | 删除后会话的记录不可获取 | 级联删除验证 |

## 十二、质量门禁

| 门禁项 | 阈值 | 说明 |
|--------|------|------|
| L1 Unit 通过率 | **100%** | 全部 P0 用例必须通过 |
| L2 Integration 通过率 | **100%** | API 端点端到端验证 |
| L3 Contract 通过率 | **100%** | 响应结构与 `09` 一致 |
| Demo 模式全覆盖 | 全部智能体 | 不配置任何 API Key 时所有功能可用 |
| 降级链完整 | 3 级 | CoPaw → 百炼 → Demo 不可跳级 |
