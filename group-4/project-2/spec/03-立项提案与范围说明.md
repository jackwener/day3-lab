## 2. 提案概要

Vibe Oracle 是一个单页交互式 3D 命运卡仪式体验。用户在暗色梦幻的视觉氛围中，通过"开始占卜"进入仪式，从 9 张 3D 卡牌中依次抽取 3 张，分别揭示"状态 / 欲望 / 结果"，最终生成个性化结局、人格报告和可分享的视觉结果卡。整个体验控制在 2 分钟内完成，适合现场多人一起玩。

## 3. 范围边界

| 做（范围内） | 不做（范围外） |
|-------------|---------------|
| 入口页与仪式动画（2秒内） | 实时多人联机 |
| 9张卡牌 3D 祭坛展示 | 登录和账号系统 |
| 三阶段命运揭示流程 | 支付功能 |
| 改命选择分支 | 重后端平台 |
| 最终结局生成 | 大模型接入关键路径 |
| 人格报告（标签+状态条） | 后台管理系统 |
| 分享卡展示 | 冗长问卷（>5题） |
| 再来一次重置 | 多页应用结构 |
| 响应式桌面/移动端适配 | 用户数据持久化存储 |

## 4. 成功标准（可度量）

| 标准 | 度量方式 |
|------|----------|
| 新用户 3 秒内知道怎么玩 | 用户测试：首次进入后 3 秒内点击"开始占卜"比例 >80% |
| 第一次翻牌有冲击力 | 用户反馈：视觉满意度评分 ≥4/5 |
| 3 张卡流程有清晰递进 | 用户测试：能正确说出三张卡含义比例 >90% |
| 结果适合截图分享 | 用户测试：愿意分享比例 >70% |
| 页面在桌面和移动端正常使用 | 测试：Chrome/Safari/Firefox 最新 2 版本通过 |
| 现场 demo 无需过多解释 | 观察：新用户首次使用无需提示完成全流程 |
| 2 小时内完成开发 | 实际开发时间 ≤2 小时 |

## 5. 风险（简表）

| 风险 | 影响 | 应对 |
|------|------|------|
| 3D 动画性能在低端设备卡顿 | 用户体验下降 | 提供降级方案（2D 翻转替代） |
| 移动端触控与悬停效果冲突 | 交互不一致 | 区分设备类型，分别实现 |
| 时间超支导致功能裁剪 | 核心体验不完整 | 严格遵循最小交付版本优先级 |
| 文案内容不够有趣 | 分享意愿低 | 准备多套文案模板快速替换 |

## 6. 立项前置条件

- ☐ 确认技术栈（React/Vue + CSS 3D 或 Three.js）

- ☐ 准备 9 张卡牌内容数据（状态/欲望/结果各 3 张）
- ☐ 准备最终结局组合规则
