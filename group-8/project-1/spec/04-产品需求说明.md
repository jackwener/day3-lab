## 1. 愿景与目标

构建研报审核助手，帮助质检团队在研报发布前高效完成合规审核与内容检查，将单份审核耗时缩短 50% 以上，P0 级合规问题漏检率趋近于零。

**痛点→目标映射**：

| 03 痛点                             | 04 目标                                  |
| ----------------------------------- | ---------------------------------------- |
| 人工审核效率低，单份耗时 10-45 分钟 | 自动化审核，单份耗时缩短至 5-20 分钟     |
| 合规风险漏检，敏感信息依赖经验识别  | 规则 + AI 双重检测，P0 漏检率趋近于零    |
| 审核标准不统一，审核员结果差异大    | 统一规则引擎，消除人为判定差异           |
| 审核记录追溯困难                    | 全量审核记录留痕，支持统计分析与问题溯源 |

## 2. 目标用户

| 角色     | 使用目标                                         | 频率        |
| -------- | ------------------------------------------------ | ----------- |
| 研究员   | 提交研报进行合规审核，查看审核报告并修改         | 每天多次    |
| 质检员   | 执行审核（选择审核模式）、查看问题详情、导出报告 | 每天持续    |
| 合规专员 | 管理审核规则（启用/禁用）、查看合规统计          | 每周多次    |
| 质检主管 | 查看仪表盘统计（通过率、趋势、TOP5 问题）        | 每天 1-2 次 |

## 3. 核心业务场景

**SC-01 提交研报审核**：用户点击"提交审核" → 上传研报文件（PDF/DOCX/DOC）→ 选择研报类型与审核模式 → 系统执行审核 → 返回审核结果（评分、问题列表）

**SC-02 查看审核报告详情**：用户在历史列表点击某条审核记录 → 查看审核评分、问题列表（含位置、严重程度、修改建议）→ 下载原始文件 → 导出审核报告 PDF

**SC-03 审核历史查询**：用户进入历史页面 → 按状态/模式/日期/关键词筛选 → 分页浏览审核记录列表

**SC-04 仪表盘统计**：质检主管打开仪表盘 → 查看概览指标（总审核数、通过率、平均分）→ 查看近 7 日趋势图 → 查看 TOP5 常见问题

**SC-05 规则管理**：合规专员进入规则管理页面 → 查看全部审核规则 → 启用/禁用特定规则

| 编号  | 场景名           | 用户路径                                  |
| ----- | ---------------- | ----------------------------------------- |
| SC-01 | 提交研报审核     | 上传文件 → 选模式 → 执行审核 → 查看结果   |
| SC-02 | 查看审核报告详情 | 历史列表 → 点击记录 → 查看问题 → 导出报告 |
| SC-03 | 审核历史查询     | 进入历史 → 筛选/搜索 → 分页浏览           |
| SC-04 | 仪表盘统计       | 打开仪表盘 → 概览 → 趋势 → TOP5           |
| SC-05 | 规则管理         | 进入规则页 → 查看规则 → 启用/禁用         |

## 6. 业务规则

| 编号  | 规则                                                                             | 来源                     |
| ----- | -------------------------------------------------------------------------------- | ------------------------ |
| BR-01 | 上传文件格式 MUST 为 PDF / DOCX / DOC，其他格式返回 `UNSUPPORTED_FILE_TYPE` 错误 | 03 §3 范围边界           |
| BR-02 | 上传文件大小 MUST ≤ 50MB，超限返回 `FILE_TOO_LARGE` 错误                         | 03 §5 假设与约束         |
| BR-03 | 审核模式 MUST 为 `rule` / `ai` / `combined` 三选一                               | 02 S-01 审核模式定义     |
| BR-04 | 研报类型 MUST 为 日报 / 周报 / 深度研究 / 首次覆盖 / 行业报告 五选一             | 02 S-02 审核模式选择建议 |
| BR-05 | 审核评分范围 0-100，综合所有问题的严重程度计算                                   | 03 §2 项目目标           |
| BR-06 | 存在 P0 级问题 → 审核状态 MUST 为 `failed`                                       | 02 S-02 审核规则梳理     |
| BR-07 | 仅存在 P1/P2 级问题 → 审核状态为 `warning`                                       | 02 S-02 审核规则梳理     |
| BR-08 | 无问题 → 审核状态为 `passed`，评分 100                                           | 02 S-02 审核规则梳理     |
| BR-09 | 审核 ID 格式为 `RV-{年份}-{4位序号}`，如 `RV-2026-0001`                          | 代码实现                 |
