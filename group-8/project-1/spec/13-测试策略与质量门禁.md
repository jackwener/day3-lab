## 一、测试分层

> 共 3 层，写测试前先搞清楚每层验什么。

| 层级               | 工具                       | 覆盖对象                                          | 说明                               |
| ------------------ | -------------------------- | ------------------------------------------------- | ---------------------------------- |
| **L1 Unit**        | pytest                     | 单个函数/类的逻辑（审核引擎、评分计算、文件解析） | 不依赖网络，最快                   |
| **L2 Integration** | pytest + Flask test_client | API 端点 + 数据库 + 业务逻辑                      | 模拟 HTTP 请求，覆盖全部 10 个端点 |
| **L3 E2E**         | 手动测试                   | 完整用户旅程（浏览器操作）                        | 当前无自动化 E2E，人工执行         |

> **注**：当前项目无 Contract 层（L3 schema 断言）和自动化 E2E（Playwright/Cypress），手动 E2E 测试覆盖完整用户旅程。

## 二、用例拆分原则

> **核心理念：数"可独立失败的点"** — 每条 TC 只回答一个问题，失败时不看代码就知道哪里坏了。

| 来源     | 计数方法                        | 示例                             |
| -------- | ------------------------------- | -------------------------------- |
| 正常路径 | 每个端点的 happy path = 1 条    | `POST /reviews → 201` = TC-001   |
| 错误码   | 每个 distinct error code = 1 条 | `UNSUPPORTED_FILE_TYPE` = TC-005 |
| 分支路径 | 每个 if/else 降级分支 = 1 条    | AI 不可用 → Mock 降级 = TC-008   |
| 筛选参数 | 每组筛选条件 = 1 条             | `status=failed` 筛选 = TC-014    |

## 四、质量门禁

| Gate-ID    | 条件                                    | 阻塞合并      |
| ---------- | --------------------------------------- | ------------- |
| **G-LINT** | `flake8` 通过（0 error）                | **是**        |
| **G-UNIT** | Unit 测试全绿                           | **是**        |
| **G-INT**  | Integration 测试全绿                    | **是**        |
| **G-COV**  | 单测覆盖率 ≥ 70%（服务层 + 模型层）     | **是**        |
| **G-AC**   | P0 验收标准全覆盖（US-001/002/003/008） | **是**        |
| **G-SEC**  | 安全扫描 0 Critical（`pip audit`）      | **是**        |
| **G-PERF** | API P95 响应 < 2000ms，规则审核 < 30s   | 否（warning） |

## 五、TDD 适用场景

| 场景                                | TDD 价值 | 建议             |
| ----------------------------------- | -------- | ---------------- |
| 简单 CRUD（规则列表、历史查询）     | 低       | 写完补测试       |
| 参数校验 / 错误码（文件类型、大小） | 中       | 建议 TDD         |
| 评分计算逻辑（P0/P1/P2 扣分）       | **高**   | **强烈建议 TDD** |
| 审核引擎（规则匹配、AI 降级）       | **高**   | **强烈建议 TDD** |
| 文件解析（PDF/DOCX 提取标题作者）   | **高**   | **建议 TDD**     |
