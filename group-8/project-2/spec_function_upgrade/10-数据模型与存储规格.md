## 1. 概念模型扩展

```
Report（研报）1 ── * StockCode（股票代码）
   │
   │  extracted_data.stock_codes[] (新增)
   │  extracted_data.core_opinions[] (变更: string[] → object[])
   │
   └── OpinionSimilarity（观点相似度）
       opinion_similarity.json (新增)
```

## 2. Report 实体变更

### 2.1 extracted_data 字段扩展

在基线 `extracted_data` 基础上新增/变更：

| 字段 | 类型 | 必填 | 约束 | 说明 | 变更类型 |
|------|------|------|------|------|----------|
| `stock_codes` | `string[]` | 是 | 标准化格式 | 提取的股票代码列表 | **新增** |
| `core_opinions` | `object[]` | 是 | — | 核心观点（结构变更） | **变更** |

### 2.2 core_opinions 对象结构（变更）

从 `string[]` 变更为 `object[]`：

| 字段 | 类型 | 必填 | 约束 | 说明 |
|------|------|------|------|------|
| `text` | `string` | 是 | ≤200 字符 | 观点摘要文本 |
| `source_text` | `string` | 是 | ≤500 字符 | 原文片段（包含前后 200 字符上下文） |
| `position` | `integer\|null` | 是 | ≥0 或 null | 在 raw_text 中的字符偏移位置 |

### 2.3 向后兼容

- V1 已有研报的 `core_opinions` 为 `string[]` 格式
- 读取时兼容处理：如果元素为 string，自动转为 `{text: str, source_text: "", position: null}`
- 新上传研报使用新格式

## 3. 新增实体 — StockMockData

> Mock 数据不持久化，内嵌 Python 代码。

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | `string` | 标准化股票代码（如 SH600519） |
| `name` | `string` | 公司名称 |
| `current_price` | `number` | 当前股价（Mock 固定值） |
| `change_percent` | `number` | 涨跌幅百分比 |
| `price_history` | `array` | 30 日价格数据 `[{date, close}]` |
| `financial_summary` | `object` | `{period, revenue, net_profit, yoy_growth}` |
| `key_events` | `array` | `[{date, event}]` |

## 4. 新增存储文件 — opinion_similarity.json

> 存储研报间观点的预计算相似度结果。

| 项 | 规格 |
|----|------|
| 文件路径 | `{DATA_DIR}/opinion_similarity.json` |
| 编码 | UTF-8，缩进 2 空格 |
| 结构 | 以研报对 ID 为键的相似度映射 |

**JSON 结构示例**：

```json
{
  "pairs": [
    {
      "report_a": "report_id_1",
      "report_b": "report_id_2",
      "common_opinions": [
        {
          "text": "业绩超预期，营收增速保持双位数",
          "opinion_a": "公司业绩超预期，营收同比增长15%",
          "opinion_b": "业绩增长超预期，营收增速达16%",
          "similarity": 0.82
        }
      ],
      "diff_opinions_a": ["新产品线拓展顺利"],
      "diff_opinions_b": ["估值偏高建议观望"]
    }
  ]
}
```

## 5. Storage 方法变更/新增

### 5.1 研报管理（变更）

| 方法 | 签名 | 行为 | 关联 TC |
|------|------|------|---------|
| `delete_report` | `(report_id) → None` | 删除元数据 + 原始文件 + 清理相似度缓存 | TC-M02-020 |
| `get_reports` | `(session_id=None, search=None, institution=None, stock_code=None) → list` | 支持多维筛选 | TC-M02-040 |

### 5.2 观点相似度管理（新增）

| 方法 | 签名 | 行为 | 关联 TC |
|------|------|------|---------|
| `save_opinion_similarity` | `(report_id, similarities: list) → None` | 保存一份研报与其他所有研报的观点相似度 | TC-M02-050 |
| `get_opinion_similarity` | `(report_ids: list) → dict` | 获取指定研报间的共同/差异观点 | TC-M02-051 |
| `delete_opinion_similarity` | `(report_id) → None` | 删除研报时清理关联相似度数据 | TC-M02-052 |

### 5.3 股票 Mock 数据（新增）

| 方法 | 签名 | 行为 | 关联 TC |
|------|------|------|---------|
| `get_stock_detail` | `(code: str) → dict\|None` | 从 Mock 数据中查询股票详情 | TC-M02-001 |

## 6. 关键业务逻辑（新增）

| 逻辑 | 触发条件 | 行为 |
|------|----------|------|
| 股票代码标准化 | 提取股票代码后 | 统一转为 `SH/SZ + 6位数字` 格式 |
| 观点位置记录 | 提取核心观点时 | 在 raw_text 中搜索观点文本，记录首次匹配的字符偏移 |
| 观点相似度预计算 | 新研报解析完成后 | 与已有所有研报的观点进行两两相似度计算 |
| 删除级联清理 | `delete_report` 时 | 删除元数据 → 删除原始文件 → 清理 opinion_similarity 中关联数据 |
| 兼容性转换 | 读取 V1 研报时 | core_opinions 从 string 自动转为 {text, source_text: "", position: null} |

## 7. 数据兼容性迁移策略

| 场景 | 处理方式 |
|------|----------|
| V1 研报无 stock_codes | 默认为空数组 `[]` |
| V1 研报 core_opinions 为 string[] | 惰性转换：读取时自动包装为 object[] |
| V1 研报无 opinion_similarity | 不影响展示，对比时共同/差异观点区域显示"无预计算数据" |
