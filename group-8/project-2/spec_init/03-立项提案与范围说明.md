## 1. 背景与问题

> 描述用户遇到的问题，至少写 2~3 条痛点。参考：信息获取、历史记录、可追溯性、系统可用性。

| 痛点 | 来源 |
|------|------|
| 信息分散：研报、新闻、数据分布在多个系统，无统一问答入口 | 用户访谈 |
| 信息提炼耗时：每日需阅读10+份长篇研报（30-50页），手动提取评级、目标价及核心观点效率极低且易遗漏。 | S-01 会议 / S-02 邮件 |
|缺乏横向对比能力：各券商研报格式不一，多份研报的核心逻辑和数据对比严重依赖人工复制粘贴到 Excel。|S-02 邮件 / S-03 访谈|

## 2. 提案概要

> 用 3~5 句话概括要做什么。参考格式："在 XXX 应用内交付 YYY 能力"。要素：会话式问答 · 能力降级 · 可追溯

在投研问答助手内交付研报智能解析、会话式问答、研报自动对比核心能力。
支持 PDF/HTML 研报自动提取评级、目标价、核心观点等关键信息。
支持自然语言会话式问答能力。
支持历史会话追溯及管理。

## 3. 范围边界

> 明确"做什么"和"不做什么"，避免范围蔓延。各写 3~4 条。

| 做（范围内） | 不做（范围外） |
|-------------|---------------|
| 会话管理：创建、列表、删除 | 多租户/行级数据权限 |
| 研报解析：PDF/HTML 格式解析，自动提取核心信息| 跳转到PDF原文引用 |
| 研报问答：自然语言交互| 股票实时行情交易数据直连（时效性高） |
| 研报对比：多份研报关键指标自动生成对比表| 舆情监控与告警（涉及外部） |

## 4. 成功标准（可度量）

> 写出 3~4 条可量化的验收标准。句式：用户在 X 分钟内完成 XXX 全链路 / 未配置外部模型时返回 XXX

| 标准 | 度量方式 |
|------|----------|
| 主路径可走通 | 用户在 3 分钟内完成"新建会话 → 提问 → 查看历史"全链路 |
| 研报解析高效| 上传 PDF/HTML 研报，1 分钟内完成关键信息提取并展示 |
| 研报对比便捷 | 选择 3 份同标的研报，2 分钟内自动生成对比表 |


## 5. 风险（简表）

> 列出 2~3 个主要风险。常见方向：外部依赖不可用、数据存储并发、模块间契约延期。

| 风险 | 影响 | 应对 |
|------|------|------|
| 外部 LLM 不可用 | 问答功能降级 | 三级降级：CoPaw → 百炼 → Demo 模式兜底 |
| PDF文档解析失真 | 提取文本错乱，问答质量崩盘 | 引入专业版面分析工具（如 PP-Structure）进行预处理|
