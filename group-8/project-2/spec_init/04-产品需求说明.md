> **04 的定位**：`03` 说了"为什么做"，04 翻译成"做什么、不做什么、多重要"。`05` 再拆成用户故事和验收标准。

## 1. 愿景与目标

> 把 `03` §1 的痛点翻译成正面目标。格式："构建 XXX，帮助用户在 XXX 内完成 XXX"。

**示例 — 痛点→目标映射**：

| 03 痛点 | 04 目标 |
|---------|---------|
| 信息分散、无统一入口 | 统一会话问答入口 |
| 复盘成本高 | 会话历史自动沉淀，随时回看 |

| 03 痛点 | 04 目标 |
|---------|---------|
| 信息提炼耗时：每日手动阅读 10+ 份研报，提取评级/目标价/核心观点效率极低 | 构建研报智能解析能力，1 分钟内完成 PDF/HTML 关键信息自动提取与展示 |
| 缺乏横向对比能力：多份研报核心数据对比严重依赖手动复制粘贴到 Excel | 构建研报自动对比能力，选择 3 份同标的研报 2 分钟内自动生成对比表 |

## 2. 目标用户

> 把 `03` §2 的一句话展开成具体角色。思考：谁会用？用来做什么？多常用？

| 角色 | 使用目标 | 频率 |
|------|----------|------|
| 投研分析师 | 快速查询投研观点与市场解释 | 每天多次 |
| 研究部经理（如王经理） | 审阅各分析师研报对比结论，跟踪关键标的观点变化 | 每周多次 |
| IT 运维人员 | 负责系统本地部署、LLM 密钥配置与数据目录管理 | 按需 |

## 3. 核心业务场景

> 把 `03` §2 提案概要拆成 4~5 条用户路径。每条场景 = 一条用户操作动线。

**示例 — SC-01**：

**SC-01 新建会话并提问**：用户点击"新会话" → 输入问题 → 获得回答（含来源标识）→ 回答自动落库

| 编号 | 场景名 | 用户路径 |
|------|--------|----------|
| SC-01 | 新建会话并提问 | （见上方示例） |
| SC-02 | 研报解析与信息提取 | 用户上传 PDF/HTML 研报 → 系统自动解析 → 展示评级、目标价、核心观点等关键信息 |
| SC-03 | 查看历史问答记录 | 用户在侧边栏选择已有会话 → 查看该会话下全部问答记录（含来源标识与耗时）→ 支持追溯复盘 |
| SC-04 | 研报多维对比 | 用户选择 3 份同标的研报 → 触发对比 → 系统自动生成关键指标对比表并展示 |

## 4. 产品规则

> 把 `03` §4 成功标准 + §3 范围约束展开成可落地的规则。参考方向：输入约束、返回字段、状态管理、降级策略。

| 编号 | 规则 | 来源 |
|------|------|------|
| R-01 | 每条提问必须绑定 `session_id` | 03 §2 "会话式问答" |
| R-02 | `query` 长度 1～500 字符，为空或超长返回明确错误 | 03 §4 "P0 全部可测" |
| R-03 | 每条回答必须携带 `answer`、`llm_used`、`model`、`response_time_ms`、`answer_source` 字段 | 09 API 规格 §3 成功响应 |
| R-04 | LLM 三级降级：优先 CoPaw → 百炼 → Demo 兜底；未配置密钥时必须返回 `answer_source=demo` 的离线演示回复，系统不得报错崩溃 | 03 §5 风险应对 |
| R-05 | 首次提问（query_count 从 0 → 1）自动以 query 前 20 字重命名会话标题；删除会话时必须级联删除所有关联问答记录 | 03 §2 提案概要 / 10 数据模型 §6 |

## 5. 能力与优先级

> `03` §3 范围表写了"做什么"，04 按 P0/P1 排优先级。P0 = 必须实现，阻塞发布；P1 = 应当实现，不阻塞首版。

| 子能力 | 优先级 | 对应场景 |
|--------|--------|----------|
| 会话管理（列表 / 新建 / 删除） | **P0** | SC-01, SC-03 |
| 问答提交与三级降级 | **P0** | SC-01 |
| 研报解析（PDF/HTML 上传，自动提取评级/目标价/核心观点） | **P0** | SC-02 |
| 问答历史记录查看与追溯 | **P0** | SC-03 |
| 研报对比（多份研报关键指标自动生成对比表） | **P1** | SC-04 |

## 6. 验收与成功标准（PRD 层）

> 从 `03` §4 可度量标准出发，加上演示条件。
> **参考句式**："种子数据 ≥ N 条下，XXX 在 N 分钟内完成"

| 标准 | 度量 |
|------|------|
| 可演示 | 种子数据 ≥ 10 条下，主路径 + 历史 + 能力状态 **3 分钟内**演示完毕 |
| 离线可用 | 未配置密钥时系统仍返回离线演示回复（`answer_source=demo`） |
| 研报解析高效 | 上传 PDF/HTML 研报后，1 分钟内完成关键信息（评级、目标价、核心观点）提取并展示 |
| 研报对比便捷 | 选择 3 份同标的研报，2 分钟内自动生成关键指标对比表 |

## 7. 与 05 用户故事的关系

> **04 定"做什么、多重要"；05 定"谁要什么、怎么验收"。** 填写完本文后，下一步进入 `05` 将场景拆成 US + AC。

| 本文（PRD） | 作用 | 05 中落地 |
|-------------|------|-----------|
| §3 核心场景 | 一条叙事场景 → 一条或多条 US | SC-01 → US-001 + US-002 |
| §4 产品规则 | 字段/状态/错误口径 | 拆入各 US 的 AC |
| §5 能力优先级 | P0 / P1 | 与各 US 优先级一致 |
