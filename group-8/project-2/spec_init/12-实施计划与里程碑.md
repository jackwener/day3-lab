## 1. 里程碑（S1～S4）

> **切分原则**：每刀切出一个**可演示的用户价值**。不是"接口写好了"，而是"能给业务看什么"。

**示例 — S1**：

**S1 会话管理**：创建/列表/删除会话 API + 前端会话侧栏 → 满足 REQ-001 部分 → 验证 TC-M01-020～025

| 阶段 | 交付要点（可演示） | 满足的 REQ/US | 验证 TC |
|------|-------------------|---------------|---------|
| **S1** 会话管理 | 会话 CRUD API + 前端侧栏 | REQ-001 部分 | TC-M01-020～025 |
| **S2** 问答核心 | POST /ask 端点 + 三级降级编排 + 前端问答交互 | REQ-002 / US-002 | TC-M01-001~005 |
| **S3** 历史记录与研报解析 | GET /records 端点 + 能力探测 + 研报上传解析（4 个端点） + 前端研报展示 | REQ-003, REQ-004 / US-003, US-004 | TC-M01-030~032, TC-M01-070~075 |
| **S4** 研报对比与收口 | 研报对比端点 + 前端对比展示 + 样式完善 + 种子数据 + 质量门禁 | REQ-005 / US-005 | TC-M01-080~082 |

## 2. WBS 任务拆分

> **拆分原则**：按**工程职责**切（路由、存储、Agent、前端），不按功能切。一个 W 可跨多个 S 迭代推进。

| 任务ID | 任务名称 | 具体内容 | DoD（指向 Spec） | 推进阶段 |
|--------|----------|----------|------------------|----------|
| W1 | 路由实现 | `agent_bp.py` 端点注册、参数校验 | 对齐 `09` 端点与错误码 | S1 起贯穿 S4 |
| W2 | 存储层 | `storage.py` JSON CRUD | 对齐 `10` 数据模型 | S1～S2 |
| W3 | Agent 编排与研报解析 | `agent.py` 三级降级 + `report_parser.py` PDF/HTML 解析 | 对齐 `08` §4 + §9 | S2~S3 |
| W4 | 前端视图 | `App.jsx` 会话侧栏 + 问答区 + 研报上传展示 + 对比表 | 对齐 `06` §3~§11 | S1~S4 |
| W5 | 研报处理与对比 | 文件上传处理 + 关键信息提取 + 多研报对比算法 | 对齐 `09` §7~§10 | S3~S4 |
| W6 | 测试门禁 | 单元/集成/Contract 测试全覆盖，质量门禁全通 | 对齐 `13` 全文 | S1~S4 |

## 5. 依赖与风险

**示例 — 依赖链**：

**S1 会话管理** → **S2 问答核心**（必须先有会话才能提问）→ **S3 历史与状态** → **S4 发布准备**

| 风险 | 影响 | 应对 |
|------|------|------|
| 上游 LLM 不可用 | 问答降级 | Demo 模式兜底 |
| 研报解析超时/失败 | 用户体验下降 | 异步解析 + 失败重试 + 友好提示 |
| 大文件上传导致内存溢出 | 服务崩溃 | 流式上传 + 50MB 限制 + 服务端校验 |
