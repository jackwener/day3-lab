## 1. 产品定位

Vibe Oracle 是一个单页交互式 3D 命运卡仪式体验，将页面本身作为体验载体，通过仪式感的视觉设计和交互流程，让用户完成一场"小型命运仪式"而非操作软件工具。

## 2. 目标用户

| 用户角色 | 描述 | 核心诉求 |
|----------|------|----------|
| 现场 demo 观众 | 观看技术展示的人群 | 快速理解产品、有视觉冲击、愿意参与互动 |
| 塔罗/运势爱好者 | 喜欢神秘学、抽象内容的用户 | 获得有趣的命运解读、愿意分享结果 |
| 小团队开发者 | 想做高视觉完成度作品的技术人员 | 学习 vibe-coding 方法、快速产出可展示作品 |
| 社交分享用户 | 喜欢截图发朋友圈/社交平台的用户 | 获得精致、可独立存在的分享内容 |

## 4. 业务流程

```
[入口页] → [点击开始占卜] → [仪式动画 2s] → [9张卡牌祭坛]
                                                    ↓
[再来一次/结束] ← [分享卡] ← [人格报告] ← [最终结局] ← [第3张卡-结果]
                                                    ↑
                                              [第2张卡-欲望]
                                                    ↑
                                              [第1张卡-状态]
                                                    ↑
                                              [改命选择] (可选)
```

**主流程步骤**：
1. 用户进入入口页，看到标题、副标题、开始按钮
2. 点击"开始占卜"，播放仪式动画（星点汇聚→扫描线→信号锁定→祭坛显现）
3. 展示 9 张卡牌 3D 祭坛
4. 用户点击选择第 1 张卡，翻转揭示"状态"
5. 用户点击选择第 2 张卡，翻转揭示"欲望"
6. 用户点击选择第 3 张卡，翻转揭示"结果"
7. （可选）展示改命选择：接受命运 / 尝试改命
8. 生成并展示最终结局
9. 展示人格报告（标签+5 个状态条）
10. 展示分享卡
11. 用户选择"再来一次"重置或结束

## 5. 数据需求

| 数据项 | 来源 | 更新频率 | 存储要求 |
|--------|------|----------|----------|
| 卡牌内容数据 | 静态配置 | 部署时 | 前端代码内 JSON |
| 结局组合规则 | 静态配置 | 部署时 | 前端代码内映射表 |
| 人格报告模板 | 静态配置 | 部署时 | 前端代码内 JSON |
| 当前会话抽卡记录 | 用户交互 | 实时 | 内存状态（React State） |
| 历史图册（可选） | 用户交互 | 每次抽卡 | localStorage 会话级 |
| 暖场测试结果（可选） | 用户输入 | 单次 | 内存状态 |

## 6. 非功能需求概要

| 类别 | 要求 |
|------|------|
| 性能 | 首屏加载 <3s，动画帧率 ≥30fps，交互响应 <100ms |
| 安全 | 无用户敏感数据，纯前端实现，无 XSS/CSRF 风险 |
| 可用性 | 桌面端 Chrome/Safari/Firefox 最新 2 版本，移动端 iOS Safari / Android Chrome |
| 可访问性 | 支持键盘操作，提供动画减少选项 |
| 国际化 | 首期仅中文，预留文案配置化 |
