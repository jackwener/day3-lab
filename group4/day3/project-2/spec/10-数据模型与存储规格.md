# 10 — 数据模型与存储规格

---

| 项 | 值 |
|---|---|
| 模块编号 | VO-001 |
| 模块名称 | Vibe Oracle 命运卡仪式体验 |
| 文档版本 | v0.3 |
| 阶段 | Design（Data） |

---

> **本文档说明**：本文档配合 `09-API接口规格.md` 使用，目标是把当前前端硬编码数据抽离为后端可存储、可查询、可复用的数据模型。数据模型按两个后端域组织：`Ritual`（抽卡会话）与 `Gallery`（图鉴/历史）。

## 1. 模型总览

| 模型 | 所属域 | 用途 |
|---|---|---|
| `Card` | Gallery | 卡牌主数据 |
| `DiceFace` | Ritual | 骰子配置 |
| `RitualSession` | Ritual | 单次命运仪式会话 |
| `RitualReveal` | Ritual | 三阶段揭示快照 |
| `Ending` | Ritual | 结局模板 |
| `Personality` | Ritual | 人格模板 |
| `ReportQuote` | Ritual | 报告引言模板 |
| `HistoryRecord` | Gallery | 历史抽卡记录 |

## 2. Card

### 2.1 字段定义

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 主键，如 `card_001` |
| `title` | string | 是 | 卡牌标题 |
| `subtitle` | string | 是 | 卡牌短描述 |
| `description` | text | 是 | 卡牌详细内容 |
| `type` | enum | 是 | `state` / `desire` / `result` |
| `phase` | enum | 是 | `past` / `present` / `future` |
| `rarity` | enum | 是 | `common` / `rare` / `legendary` |
| `cover_url` | string | 否 | 卡面图 |
| `illustration_url` | string | 否 | 详情图 |
| `tags` | json | 否 | 标签列表 |
| `weight` | int | 否 | 抽取权重，默认 100 |
| `is_active` | bool | 是 | 是否启用 |
| `created_at` | datetime | 是 | 创建时间 |
| `updated_at` | datetime | 是 | 更新时间 |

### 2.2 约束

- `id` 唯一。
- `type` 与 `phase` 一一对应：
  - `state -> past`
  - `desire -> present`
  - `result -> future`
- 初始最少录入 9 张卡：每类 3 张。

## 3. DiceFace

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `face` | int | 是 | 1-6 |
| `label` | string | 是 | 展示标签 |
| `rotation` | string | 是 | 前端动画用 transform |
| `weight` | int | 否 | 权重 |

## 4. RitualSession

### 4.1 字段定义

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 主键，如 `ritual_20260415_xxxx` |
| `state` | enum | 是 | `initialized` / `dice_rolled` / `drawing` / `revealed` / `finalized` |
| `enable_dice` | bool | 是 | 是否开启骰子 |
| `dice_face` | int | 否 | 本轮骰子结果 |
| `fate_choice` | enum | 否 | `accept` / `change` |
| `selected_card_ids` | json | 否 | 3 张已选卡 ID |
| `report_payload` | json | 否 | 最终报告快照 |
| `created_at` | datetime | 是 | 创建时间 |
| `updated_at` | datetime | 是 | 更新时间 |
| `finalized_at` | datetime | 否 | 完成时间 |

### 4.2 设计理由

- 用 `report_payload` 固化最终报告，避免图鉴历史回放时重新计算导致内容漂移。
- `selected_card_ids` 用于保证 reveal/report 一致。

## 5. RitualReveal

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `ritual_id` | string | 是 | 外键，关联 `RitualSession.id` |
| `phase` | enum | 是 | `past` / `present` / `future` |
| `label` | string | 是 | 中文标签 |
| `label_en` | string | 是 | 英文标签 |
| `sub_label` | string | 是 | 副标题 |
| `rarity` | enum | 是 | 阶段稀有度 |
| `card_id` | string | 是 | 对应卡牌 |
| `sort_order` | int | 是 | 1 / 2 / 3 |

约束：
- `(ritual_id, phase)` 唯一。
- 每个 `ritual_id` 必须恰好有 3 条 reveal 记录。

## 6. Ending

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 主键 |
| `title` | string | 是 | 结局标题 |
| `summary` | string | 是 | 结局摘要 |
| `description` | text | 是 | 结局全文 |
| `mood` | enum | 是 | `epic` / `calm` / `chaos` / `ironic` 等 |
| `theme_color` | string | 是 | HEX 色值 |
| `match_rule` | json | 是 | 匹配规则 |
| `priority` | int | 否 | 优先级 |

说明：
- `match_rule` 可存精确组合，也可存降级规则。
- 最少配置 5 个精确结局 + 1 个 fallback。

## 9. HistoryRecord

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 主键，如 `history_20260415_xxxx` |
| `ritual_id` | string | 是 | 关联 `RitualSession.id` |
| `ending_id` | string | 是 | 关联 `Ending.id` |
| `personality_id` | string | 是 | 关联 `Personality.id` |
| `cover_card_ids` | json | 是 | 三张卡 ID |
| `report_payload` | json | 是 | 历史详情快照 |
| `created_at` | datetime | 是 | 创建时间 |

## 10. 前端字段映射

| 前端 mock 字段 | 后端模型来源 | 说明 |
|---|---|---|
| `tarotCardPool[].id` | `Card.id` | 保持唯一 ID |
| `tarotCardPool[].name` | `Card.title` | 标题统一改名为 `title` |
| `tarotCardPool[].description` | `Card.subtitle` | 短描述 |
| `fateCards[].phase` | `RitualReveal.phase` | RevealPage 数据源 |
| `fateCards[].rarity` | `RitualReveal.rarity` | 阶段稀有度 |
| `fateAttributes` | `report_payload.attributes` | 不再单独静态存储 |
| `reportQuotes` | `ReportQuote` -> `report_payload.quote` | 运行时生成 |
| `systemTerms` | `report_payload.systemTerms` | 运行时生成 |

## 11. 存储方案

### 11.1 持久化边界

| 数据 | 存储方式 | 说明 |
|---|---|---|
| 卡牌主数据 | 数据库表 `cards` | 由图鉴接口统一读取 |
| 结局/人格/引言模板 | 数据库配置表 | 由抽卡报告统一生成 |
| 抽卡会话 | 数据库表 `ritual_sessions` | 支撑前后端联调和排查 |
| 图鉴历史 | 数据库表 `history_records` | 替代原 localStorage |

### 11.2 本地存储降级

如果后端未接入正式用户系统，可允许前端额外缓存：

| 键名 | 内容 | 作用 |
|---|---|---|
| `vibe-oracle-last-ritual-id` | 最近一次 `ritualId` | 页面刷新后恢复 |

注意：
- 本地缓存不是主存储。
- 历史图鉴以数据库为准，不再以 localStorage 为准。

## 12. 数据校验规则

| 规则 | 校验时机 | 失败处理 |
|---|---|---|
| `selected_card_ids` 长度必须为 3 | reveal 请求时 | 返回 `VALIDATION_ERROR` |
| `selected_card_ids` 不可重复 | reveal 请求时 | 返回 `VALIDATION_ERROR` |
| `ritual_session.state` 必须合法流转 | 每次状态变更 | 返回 `RITUAL_STATE_INVALID` |
| `history_record.report_payload` 不可为空 | finalized 后写历史时 | 拒绝落库 |
| `Card.type/phase` 必须匹配 | 配置导入时 | 导入失败 |

## 13. 建议建表顺序

1. `cards`
2. `dice_faces`
3. `endings`
4. `personalities`
5. `report_quotes`
6. `ritual_sessions`
7. `ritual_reveals`
8. `history_records`
